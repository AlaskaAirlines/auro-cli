# AB#1658124

## Executive Summary

Figma's Code Connect feature shows real code snippets next to an Auro component in Figma. Until now, each of those links was written by hand, one file per component, in a separate repository, so the code shown in Figma could drift from what the component really supports.

This change extends Auro's documentation command: `auro docs --cem`, `auro build` and `auro dev` now also generate the Code Connect file whenever they build the component's machine-readable description. It reads the component's machine-readable description and the component's design data in Figma, and writes the Code Connect file automatically. It also produces a short report of the component options that Figma does not cover yet, and a small table where designers and engineers record how Figma option names map to code. A companion check (`--figma-check`) lets CI confirm those files are current without needing network access or a Figma login.

The step is skipped when the description build is skipped (`--skip-docs`, or `auro docs` without `--cem`), is skipped with a warning when no Figma token is set, and currently points at a Figma test copy rather than the production Figma file. See Ticket Completeness for what remains.

## Technical Research Document

[TRD: Code Connect generation (GitHub Discussion #658)](https://github.com/orgs/AlaskaAirlines/discussions/658). The discussion body could not be read while writing this post-mortem (the org discussion's backing repository could not be resolved), so no summary of it is included.

## The Problem

Each Figma-to-code link for an Auro component was maintained by hand in a separate repository. When a component changed, someone had to notice and update its file. New components received no link until someone wrote one. The result was code examples in Figma that could silently disagree with the real component, and coverage limited to the components someone found time for.

## Root Cause

The component's machine-readable description (`custom-elements.json`, the Custom Elements Manifest or CEM) holds the code side of a Code Connect file: attribute names, allowed values, defaults and slots. It does not hold the Figma side: the component set's node URL, Figma property names, variant option names or layer names. Every existing mapping depends on those, so there was nothing in the build that could produce a Code Connect file, and no place where the two sides were reconciled.

## The Fix

`codeConnect()` (`src/scripts/figma/code-connect.ts`) runs right after every CEM build: in `auro docs --cem` (`src/commands/docs.ts`) and in `analyzeComponents()` (`src/scripts/analyze.js`), which `auro build`, `auro build --watch` and `auro dev` use. It is therefore skipped whenever CEM generation is skipped. In `docs --cem` a non-zero exit code is passed through (previously the generic handler turned it into exit 1); in the build path it fails the docs step. The build path passes `quiet` so repos with no Code Connect config print nothing. In order:

1. `resolveFigmaContext` (`context.ts`) finds `custom-elements.json` and the custom-element tag, and keeps only tags listed in `figma-connector.config.ts`. A repo with no configured tag is skipped with exit 0. More than one configured tag in one component directory, or a missing CEM when `figma/` exists, exits 2. Monorepo layouts are handled by limiting the CEM to the component's module path.
2. `fetch-figma.mjs` calls the Figma REST API (`/v1/files/:key/nodes?ids=`) using `FIGMA_ACCESS_TOKEN` and saves each component set to `figma/snapshots/<node-id>.json`. This happens on every run; without `FIGMA_ACCESS_TOKEN` the whole step is skipped with a warning and exit 0.
3. `gen-cem-map.mjs` writes `dist/figma/<tag>.cem-map.json`, the code-side inventory of attributes and slots, with deprecated and non-public members flagged. When the CEM was built with the logical CEM annotations, each attribute and slot also carries `category`, `relevantWhen` and `requiredWhen`; an older CEM has none of them and they are left out.
4. `build-mismatch.mjs` refreshes `figma/<tag>.mismatch.md`, listing Figma properties and CEM attributes that are not matched, with design-related attributes first. If the CEM has categories, attributes that are not `ui` and not in the config's design list are not bound and get their own "not bound" section.
5. `build-translate.mjs` creates or tops up `figma/<tag>.translate.md` with `TBD` rows for new gaps. People fill these rows in to say how a Figma option maps to code.
6. `build-figma.mjs` writes `dist/figma/<tag>.figma.ts`: one `figma.connect()` group per Figma component set (and per variant state), with literal URLs, `props` (`figma.enum`, `figma.boolean`, `figma.string`), an `html` example and an `imports` entry (`// npm install <package>@<version>` plus `import '<package>';`, the version read from `package.json`, falling back to the latest CHANGELOG entry for `0.0.0`). An attribute with `requiredWhen` is never left empty: a required boolean is not bound (with a warning), and a required enum option that no translate row maps takes the attribute's default, marked in the file with `// default value: <attr> is required` (with no default, it is warned about and stays empty). Output is deterministic: no network, no timestamps.

`--figma-check` runs steps 3 to 6 in check or validate mode. It never fetches and never writes committed files, and exits 1 when the mismatch or translate file is stale, or the translate file is missing. Exit codes: 0 ok, 1 stale (`--check` only), 2 bad input.

Tests are in `test/figma.command.test.ts` with `button` and `hyperlink` fixtures that compare generated files against reference output and run each generated `.figma.ts` through the Code Connect `html` parser (`figma connect parse`, from the `@figma/code-connect@1` devDependency). The Figma API is mocked from the saved snapshots. The README documents both options.

## Why This Works

- The code side comes from the CEM, so it follows the component. The Figma side comes from a small checked-in config plus the live Figma data, so nothing is invented: the generator only binds a Figma property to a CEM attribute when a name rule or a human-written translate row says so, and everything else is listed in the mismatch file.
- Only public, non-deprecated attributes are bindable (`binding-core.mjs`); in a CEM with categories only `ui` and design-list attributes are, so behavior and data attributes do not end up in design snippets. Fallback defaults for required enums are not counted as matches in the mismatch report, so they still show as gaps. Every emitted value is a literal with no ternaries in the `html` template, which is what the Code Connect `html` parser requires.
- Generated files go to the gitignored `dist/figma/`, so existing hand-written mappings in the `code-connect` repository are never touched.
- A normal build still needs no `FIGMA_ACCESS_TOKEN` or Figma network access: without a token the step is skipped with a warning. Watch-mode rebuilds are throttled to one per 5 seconds, and the Code Connect outputs (`dist/figma/`, `figma/`) are not part of the Rollup module graph, so they cannot trigger a rebuild loop. With a token, each CEM rebuild refetches from the Figma API. `--figma-check` is offline so CI needs no token.
- `@figma/code-connect` is a devDependency only, used by the tests. It must stay on v1: v2 removed the framework parsers, including `html`.
- Exit 0 for components not in the config lets the command be wired into CI everywhere without breaking repos that have not opted in.

## Outcome

Teams can now generate a component's Code Connect file from the component itself instead of writing it by hand. The first two components, Button and Hyperlink, are covered by reference tests. CI can check that the supporting files are current without any Figma credentials. Normal builds are unaffected and nothing existing was changed or overwritten. The code examples are generated whenever the component description is built, including normal builds, and carry the package version for installs. Form-component packages (auro-formkit) are out of scope for now, and the files point at a Figma test copy.

The Code Connect and docs command tests pass (34 of 34 under Node 22.18).

**Resolved**

- Props and examples come from the CEM's public attributes and named slots; deprecated and private members are left out (and, in a CEM with categories, so are non-`ui`, non-design ones), values are literals, no ternaries (`gen-cem-map.mjs`, `binding-core.mjs`, `build-figma.mjs`).
- Figma node URLs and mappings come from a documented config (`figma-connector.config.ts` plus `figma/<tag>.translate.md`); a component with no config is skipped with a clear message and exit 0.
- Hand-written mappings are never overwritten: output goes to the gitignored `dist/figma/`, and nothing writes to the `code-connect` repository.
- The README documents the new step, its config and where files are written.
- Builds stay offline-safe and there is no breaking change: `auro build` is untouched, a missing Figma token only skips the step with a warning, and the only new dependency is a devDependency.
- Every generated file passes the Code Connect `html` parser (`npx figma connect parse`): tested for the button and hyperlink fixtures with `@figma/code-connect@1`.
- Generation is skipped when CEM generation is skipped, and runs every time the CEM is generated (`auro docs --cem`, `auro build`, `auro dev`). Watch-mode rebuilds do not retrigger it (see Why This Works).
- `auro build` (and `auro docs --cem`) generates the `.figma.ts` for the component in the config (`analyze.js`, `docs.ts`).
- Generated files follow the `code-connect/mapping` pattern, including `imports`: `// npm install <package>@<version>` and `import '<package>';` per `figma.connect` (`build-figma.mjs`, covered by the fixture tests and the parser test). The `imports` comment line has not been checked in the Figma MCP server; if it is dropped there, the version should move into a `links` entry.

## Learnings

- The CEM cannot supply the Figma side. Any generator needs a source for node URLs and option names; here that is the config in auro-cli, so adding a component or changing a node id needs an auro-cli release.
- `FIGMA_FILE` currently points at the fork test file (`Auro-toolkit---Fork---Code-Connect-Test`). The production file URL appears only in a comment. With `--figma-publish` removed, the generated output always references the fork until `FIGMA_FILE` is switched.
- Every CEM build (`auro docs --cem`, `auro build`, `auro dev`) fetches Figma data and needs `FIGMA_ACCESS_TOKEN` (without it the step is skipped with a warning); `--figma-check` reads the saved snapshots and never touches the network, which is what keeps CI token-free.
- Category scoping and required-attribute handling go beyond what the ticket lists. They are covered by tests that annotate the button fixture's attributes (`category`, `requiredWhen`); they have not been run against a real CEM built with the logical annotations, and a CEM without them binds every bindable attribute as before.
- The `.figma.ts` output is gitignored. The committed files are `figma/<tag>.translate.md`, `figma/<tag>.mismatch.md` and `figma/snapshots/`, and `--figma-check` is what keeps them in sync.
- The tests need Node 22.18 or newer (TypeScript type stripping) and the repo loader: `node --import ./test/register.mjs --test ...` (this is what `npm test` runs). Plain `node --test` fails to resolve the `.js` import specifiers.
- Version guidance for AI tools (keep an installed version, install the version in the snippet, one major per page) belongs in agent instructions such as the Auro Claude plugin, not in the generated file. One Figma library per npm major version and a published compatibility manifest are process decisions outside auro-cli.
- When removing CLI options, grep for other callers first. The removed options had none in other commands or workflows.

## Iterations That Didn't Work

- A larger option surface was built first: separate `--figma-fetch`, `--figma-nodes`, `--figma-tag`, `--figma-commit` and `--figma-publish` flags, plus a `--commit` flag in `build-figma.mjs`. They were dropped because users would not call them and always fetching and generating all files as part of `--cem` is simpler. The cost is that the generated header no longer records a commit, and the output can no longer be pointed at the production Figma file without editing the config.
- Supporting several configured components in one directory (via `--figma-tag`) was replaced with an error: more than one configured custom element in a component directory exits 2.
