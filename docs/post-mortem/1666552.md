# AB#1666552

## Executive Summary

Auro's release tooling now has a way to check that each change gets the right version number. A new command, `auro api-diff`, compares what a pull request actually changed with what its commit messages claim. It reports the smallest version bump the change needs (patch, minor or major) and flags the pull request when its commits claim less. For example, it catches a change labeled as a small fix that removes a public option.

This is the first phase of a larger plan. It delivers the analysis tool in auro-cli. Running the check on pull requests, blocking merges, and the safety net at release time come in later phases, in other repos.

Ticket: [AB#1666552](https://itsals.visualstudio.com/E_Retain_Content/_workitems/edit/1666552)

## Technical Research Document

[Verifying Release Versions Against Code Changes](https://github.com/orgs/AlaskaAirlines/discussions/661). Proposes a check that works out the minimum bump a PR's code changes require (from `custom-elements.json`, `package.json` and changed files) and fails PRs whose commits declare less. It rolls out in phases: measure, analyzer, report-only, enforce, release-time safety net, and old-test replay.

## The Problem

Each Auro release gets its version number only from how engineers label their commits. Nothing checks those labels against the code. A change that removes a public option, labeled as a small fix, ships as a patch release. Teams that take patch updates automatically can then have their pages break. It also goes the other way: test-only changes trigger needless releases, and real code changes labeled as housekeeping don't release until some unrelated release goes out. Our version numbers are a promise to the teams that use Auro, and today keeping that promise depends on every engineer labeling every commit correctly.

## Root Cause

- `@semantic-release/commit-analyzer` (configured by `@aurodesignsystem/auro-config/releaserc`) picks the bump only from the commit type, `!`, and `BREAKING CHANGE` footers. commitlint checks that messages are well formed, not that the type matches the change. No tool compared the declared bump with the code diff.
- The only commit classifier in auro-cli, `auro check-commits`, uses a hand-rolled `RELEASE_COMMIT_TYPES` list instead of the release's own rules. Any check built on it could disagree with the actual release.
- An additional trap came up during implementation, documented in `src/scripts/api-diff/declared.ts`. With `conventional-changelog-conventionalcommits` 7, which auro-config 1.3.1 pulls in, commit-analyzer 13 ignores the preset's parser options. A `feat!:` header without a `BREAKING CHANGE:` footer then releases nothing. So the declared bump depends on which analyzer and preset versions are installed, not only on the config.

## The Fix

This change adds `auro api-diff <baseRef> [headRef]` (`src/commands/api-diff.ts`, registered in `src/index.ts`), backed by `src/scripts/api-diff/`:

- **`index.ts` (`runApiDiff`)**: resolves both refs and their merge base. All comparisons start from the merge base, so only the PR's own changes and commits count. It collects classified changes, computes `required` (highest bump) and `declared`, and returns `{ required, reasons, declared, outcome, summary, … }`. `formatSummary` produces the TRD's PR-comment sentence. If only `test/`, `tests/`, `.github/` or `docs/` changed, it skips the manifest rebuild.
- **`git.ts`**: `buildManifestAt` checks out each ref in a temporary `git worktree`, runs the install and build commands (`npm ci`, `npm run build` by default, with `HUSKY=0`), reads the manifest, and always removes the worktree. `listCommits` uses `--no-merges` plus a `Merge pull request|branch|remote-tracking branch` subject filter, and returns commits newest first, as semantic-release expects.
- **`manifest-diff.ts` (`diffManifests`)**: compares elements by tag and members by `privacy` (never by name prefix). An attribute counts as public unless it's `internal` or backed by a non-public field. The rules:
  - Removals, renames, made-private members, narrowed or replaced types, attributes that stop reflecting, and any default-value change are **major**.
  - Additions, made-public members, and widened types are **minor**.
  - `normalizeValue` and `splitUnion` normalize quotes and whitespace and split unions only at the top level.
- **`package-diff.ts`**: `diffPackageJson` classifies `exports` subpaths (and introducing `exports` at all), `main`, `types`, `typings`, `files`, peer and runtime dependency major bumps (treating `0.x` minor as breaking), and tightened or new `engines`. `diffChangedFiles` requires a patch for `src/`, `demo/` or `README.md`, matched per path segment so monorepo layouts count.
- **`declared.ts`**: `loadAnalyzerConfig` resolves the repo's own release config (`.releaserc`, `.releaserc.json`, or `package.json#release`) and follows `extends` the way semantic-release does. A repo's own analyzer plugin wins, so auro-formkit's copied `.releaserc` is honored. When nothing resolves, it falls back to `SHARED_ANALYZER_OPTIONS`, which mirror auro-config's custom rules (`refactor`/`style` → patch, `docs(README)` → patch). `loadAnalyzer` prefers the commit-analyzer in the repo's `node_modules` and otherwise uses auro-cli's own copy. `declaredBump` runs one pass over all commits, so reverts cancel out as they do at release, plus a pass per commit for the report.
- **`bump.ts`**: `compareBumps` returns `fail` (declared lower than required), `warn` (no release needed but one declared), or `pass`.
- **CLI contract**:
  - `--json` writes only JSON to stdout.
  - Without `--enforce` the command always exits 0 (report-only); with `--enforce` it exits 1 on `fail`.
  - Exit 2 means the analysis couldn't run.
  - Other options: `--no-rebuild`, `--manifest`, `--install-command`, `--build-command`.
- Adds the dependencies `@semantic-release/commit-analyzer`, `conventional-changelog-conventionalcommits` 9, and `semver`, a type shim (`src/semantic-release.d.ts`), README docs, and four test files.

## Why This Works

- **The check and the release can't disagree.** The declared bump comes from the same library, the same config resolution, and preferably the same installed versions the release uses. That avoids the `check-commits` drift and the preset-version trap above.
- **The committed manifest isn't trusted.** Rebuilding at both refs means a stale or hand-edited `custom-elements.json`, or a repo that doesn't commit one, can't hide an API change. `--no-rebuild` exists as an explicit, documented opt-out.
- **Failure behavior is defined.** A head that won't build is an error (fail closed). A base that won't build falls back to its committed manifest, then to skipping the API comparison, with a warning (fail open). A PR shouldn't be blocked by a base it didn't break.
- **Merge-base scoping** makes "reconcile dev with main" PRs come out as no change, and keeps the result stable however far `dev` has moved.
- **Privacy-field filtering** matches how Auro's manifests actually mark private members, since most don't start with `_`. Quote normalization keeps formatting-only default changes from causing false majors.
- **Minimum, not exact match.** Declaring more than required passes, because behavior can break without the API changing.
- **Report-only by default.** Shared workflows run `npx @aurodesignsystem/auro-cli` at latest, so this release can't block any repo until a workflow opts into `--enforce`.

## Outcome

Auro now has a working tool that tells, for any pull request, which version bump the change needs, what the commits claim, and whether the claim is high enough, with a plain-language reason for each finding. It is ready to be wired into pull-request checks in report-only mode. Nothing is blocked yet, and no published component changes.

## Learnings

- **Read the declared bump the way the release does, with the release's own installed versions.** Re-implementing commit-type rules (as `check-commits` does) or pinning one analyzer version invites drift. With `conventional-changelog-conventionalcommits` 7, commit-analyzer 13 ignores `feat!:` without a `BREAKING CHANGE:` footer.
- **Repos with a copied `.releaserc` (auro-formkit) must be read from their own config, not assumed to extend auro-config.** `loadAnalyzerConfig` handles this, but the Phase 4 release plugin will still not reach them.
- **Filter API privacy on the manifest's `privacy` field, never on `_` prefixes.** Most Auro private members have ordinary names. Reliable `privacy` data depends on the `cem-check --strict` rollout (AB#1657999).
- **Scope every comparison to the merge base**, so reconcile PRs and long-lived branches don't pick up unrelated changes.
- **Decide fail-open vs fail-closed explicitly** for any check that has to build two refs: fail closed on the head, fail open on the base.
- **Anything shipped in auro-cli reaches every repo immediately** through `npx` at latest, so new checks should default to report-only and enforcement should be opt-in.
