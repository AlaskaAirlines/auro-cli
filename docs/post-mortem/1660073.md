# AB#1660073

## Executive Summary

Every Auro component's README and demo pages are generated by the Auro CLI from
smaller documentation pieces. Before this change, a broken piece did not stop
the build: the CLI logged a message, reported success, and the component could
ship with a README that was missing sections or still showed raw template text.
Code examples on those pages were also quietly altered. Blank lines carried an
invisible character, and some lines gained extra blank lines, so code an
engineer copied did not always match what the component team wrote.

Now the docs build fails loudly. It still generates every page it can, then
stops with a list of every page that broke and why, so problems are caught
before release instead of by consumers. Code examples are reproduced exactly as
written, so they can be copied and run as-is.

This is a breaking change for component teams: a component whose docs were
quietly broken will now fail its build until the docs are fixed. Components
created before Auro CLI v4 must add two (possibly empty) documentation files
that the current README template expects.

Ticket: [AB#1660073](https://itsals.visualstudio.com/E_Retain_Content/_workitems/edit/1660073)
— *Make the auro-cli docs build fail on broken READMEs and copy code snippets
unchanged*.

## The Problem

Component teams rely on `auro build` and `auro docs` to produce their README
and demo pages. Two things went wrong silently:

- **Broken docs were published as if they were fine.** If a documentation piece
  was missing, or a template value couldn't be filled in, the build still
  reported success. The result could be a README with empty sections or literal
  `{{ … }}` template text. Automated pipelines had no way to notice, because
  the command did not report a failure.
- **Code examples didn't copy cleanly.** Blank lines inside code samples
  contained an invisible character, so pasted code could fail to run or behave
  oddly. Some samples (CSS with `#id` rules, shell scripts with `#` comments)
  gained extra blank lines that the author never wrote. Framework examples
  using `{{ }}` syntax (Vue, Angular, Handlebars) could have those expressions
  erased entirely.

## Root Cause

- **Per-file errors were swallowed.** `processDocFiles` in
  `src/scripts/build/defaultDocsBuild.js` wrapped each file in a `try/catch`
  that only called `Logger.error` and moved on. Nothing was rethrown, so
  `auro build` and `auro docs` exited 0 regardless of failures.
- **Missing nested includes were skipped.** The second-pass resolver in
  `postProcessMarkdownFile` only handled `FILE`/`CODE` tags whose source
  existed. A missing source was silently left as an empty generated block.
- **Handlebars blanked anything it didn't recognize.** auro-library's template
  filler runs Handlebars, which renders an unknown `{{ expr }}` as an empty
  string. That erased framework syntax in code samples and hid misspelled
  template variables in prose (`{{ nmae }}` became nothing rather than an
  error).
- **The second pass re-filled the whole file.** After inlining nested
  includes, `templateFiller.replaceTemplateValues` ran over the entire output
  again. That re-processed content the first pass had already produced,
  including literal `{{ name }}` text that an author had escaped as
  `\{{ name }}`.
- **Blank lines in code were encoded as U+200B.** The `<pre><code>`
  post-processor replaced blank lines with a zero-width space so marked.js
  wouldn't end the HTML block early. The invisible character then ended up in
  anything a reader copied.
- **auro-library edited code bodies.** In versions before 5.14.4, the
  library's line-break cleanup also touched code, inserting blank lines before
  lines starting with `#`.
- **String replacement expanded `$` patterns.** Inlined content was spliced in
  with `String.prototype.replace(fullMatch, replacement)`, so `$$`, `$&`, `$'`
  and `` $` `` inside a snippet were interpreted as replacement patterns.
- **`auro docs` had no top-level error handling.** A failure surfaced as an
  unhandled promise rejection instead of a clean non-zero exit.

## The Fix

- **Aggregate and throw.** `processDocFiles` records each failing file in a
  `failures` list, keeps processing the rest, then throws one error listing
  every failed file.
- **Report missing nested includes.** `postProcessMarkdownFile` collects
  missing `FILE`/`CODE` sources (deduplicated, because the scan restarts after
  each replacement) and throws `Included file(s) not found: …`.
- **Placeholder check.** After post-processing, `findUnreplacedPlaceholders`
  scans the generated markdown with code regions (`<pre>`, `<code>`, fenced
  blocks, inline spans) removed, and fails the file if any `{{ … }}` remains in
  prose.
- **Escape before Handlebars.** A new pre-processor,
  `escapeUnknownPlaceholders`, runs just before auro-library's Handlebars pass.
  It leaves known template variables (`TEMPLATE_VARIABLES` plus `extraVars`)
  and known helpers with variable or string-literal arguments
  (`TEMPLATE_HELPERS`) alone and backslash-escapes everything else. In code,
  Handlebars block, comment, partial and triple-stash syntax is escaped too, so
  it survives literally. In prose, unknown expressions survive literally and
  are then caught by the placeholder check.
- **Fill only inlined content.** The second pass no longer re-fills the whole
  file. `fillInlinedContent` fills template values only in the content being
  inlined. `CODE` includes are wrapped in `<pre>` *before* filling, so the
  filler's prose cleanup skips them.
- **Function replacer.** Inlining uses `replace(fullMatch, () => replacement)`
  so `$` sequences in snippets are not expanded.
- **`&#10;` instead of U+200B.** Blank lines inside `<pre><code>` end with an
  encoded newline (`&#10;`), which marked.js and GitHub render, and browsers
  copy, as a real newline. Lines are split on `\r?\n` so CRLF files don't leave
  a stray `\r`.
- **auro-library `^5.14.4`.** This version stops the library's line-break
  cleanup from editing code bodies.
- **Command behavior.** `auro docs` is now `runDocs` in `src/commands/docs.ts`,
  which reports failures with `ora().fail` and calls `process.exit(1)`.
  `docs()` in `src/scripts/docs/index.ts` still builds the demo when the docs
  build fails, then rethrows. In watch mode (`runDocs` with `--watch`,
  `watchDocs`, and `handleWatcherEvents`), a docs failure is reported but the
  server and watcher keep running.
- **CI and docs.** `test-and-release.yml` adds an `npm ls --omit=dev` check of
  the production dependency tree. The README documents the failure rules,
  which `{{ }}` expressions are filled in snippets, and the two partials that
  pre-v4 components must add.
- **Tests.** New fixture tests in `test/defaultDocsBuild.test.ts`,
  `test/docs.command.test.ts` and `test/watchModeHandlers.test.ts` cover
  failure aggregation, missing nested includes, the placeholder check,
  framework syntax, escapes, `$` patterns, blank and CRLF lines, `#`-line
  preservation, exit codes and watch-mode resilience.

## Why This Works

- **A single, complete error.** Collecting failures before throwing means one
  build run reports every broken page, not just the first, while the pages
  that work are still generated.
- **Nothing is blanked silently anymore.** Every `{{ … }}` the template filler
  can't resolve is either escaped and kept (code) or left in place and flagged
  (prose). A typo in a template variable becomes a build error naming the
  placeholder, instead of a quietly missing word.
- **Code and prose follow different rules on purpose.** Framework examples
  legitimately contain `{{ }}`, so code regions are excluded from the
  placeholder check and get stricter escaping. Template variables and helpers
  are still filled in code, so `{{ withAuroNamespace "button" }}` keeps working
  in snippets.
- **Each piece of content is filled exactly once.** Filling only the inlined
  content in the second pass preserves the author's `\{{ name }}` escapes from
  the first pass.
- **`&#10;` is a real newline once rendered.** Unlike U+200B, it doesn't put an
  invisible character into copied code, and it still prevents marked.js from
  treating a blank line as the end of the HTML block.
- **Watch mode stays usable.** Failing the whole dev server because of one
  unrelated docs page would stall development. Reporting the error and
  rebuilding on the next change keeps the feedback loop intact, while one-shot
  builds (`auro build`, `auro docs`, CI) fail hard.

## Outcome

- A component with broken documentation can no longer pass its build. The team
  sees a single message listing every broken page and the reason.
- Code examples in READMEs and demo pages match the source exactly: no
  invisible characters, no added blank lines, and framework template syntax
  intact.
- Local development is unaffected by a docs error: the dev server and watchers
  keep running and pick up the fix automatically.
- Component teams on older templates have clear upgrade instructions in the
  CLI README.

**Resolved**

## Learnings

- **A build step that logs and continues must still fail at the end.** A
  `try/catch` that only logs turns every error into a success. Collect the
  failures and throw once all work has run.
- **Handlebars is lossy by default.** Unknown expressions render as empty
  strings. Any pipeline that feeds user-authored content through Handlebars
  needs an allowlist of expressions to fill and an escape step for everything
  else.
- **Keep `TEMPLATE_VARIABLES` / `TEMPLATE_HELPERS` in sync with auro-library's
  `AuroTemplateFiller`.** A variable missing from the list fails the build
  loudly rather than being dropped, so drift will surface, but the list must be
  updated when the library adds variables.
- **Don't use invisible characters as layout workarounds.** They leak into
  copied output. Use an HTML entity that renders as the intended character.
- **Pass a function to `String.prototype.replace` when the replacement is
  arbitrary content.** A string replacement interprets `$` patterns.
- **Run a template pass over each piece of content exactly once.** Re-filling
  already-rendered output undoes escapes.
- **Treat watch mode and one-shot builds differently.** Fail hard in CI and
  one-shot commands. In watch mode, report the error and keep serving.
- **Known gap:** a failed `REMOTE` include (for example, a 404 on a remote
  partial) still produces an empty section and exits 0. This was out of scope
  for this ticket and is a candidate for a follow-up ticket.
